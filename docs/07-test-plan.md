# 知伴：测试计划

## 1. 测试目标与原则

测试重点不是证明模型“永远回答正确”，而是证明系统在模型输出不确定、外部依赖失败、并发和恶意输入下仍保持边界明确、数据隔离、状态一致，并给用户可理解的结果。

原则：

- 可确定逻辑优先使用单元测试；数据库、Redis、SSE、Worker 使用真实依赖的集成测试。
- LLM、搜索和提醒投递默认使用可编程 Fake/Mock，真实 provider 只做少量契约测试。
- 时间相关测试使用 Fake Clock，禁止依赖长时间 `sleep`。
- 所有写工具和任务消费都验证幂等；不以“恰好一次”作为前提。
- 安全测试覆盖 API、Agent、Tool、Memory、日志和 Worker 全链路。
- 本文给出计划和门槛，不表示这些测试已经执行；结果必须以实际 CI/测试报告为准。

## 2. 测试金字塔

建议按数量和反馈速度分配：

- **单元测试，约 55%～65%**：纯函数、状态机、schema、Token 预算、排序、重试判定、时间解析、脱敏。
- **组件/集成测试，约 20%～30%**：PostgreSQL/pgvector、Redis、repository、SSE、Worker、Tool Executor。
- **API/契约测试，约 8%～12%**：认证、分页、错误格式、OpenAPI、SSE 事件协议。
- **E2E，约 5%～8%**：只覆盖最关键用户旅程和故障降级，避免把所有组合堆到浏览器层。
- **性能、安全、恢复专项**：合并前跑轻量集，主分支定时或 release 前跑完整集。

## 3. 编号规范

- `UT-xxx`：无外部依赖的单元测试。
- `IT-xxx`：数据库、Redis、Worker 等集成测试。
- `API-xxx`：HTTP/SSE 接口和契约测试。
- `AG-xxx`：Agent 编排、上下文与 LLM 异常。
- `MEM-xxx`：记忆写入、合并、检索、遗忘与隔离。
- `TOOL-xxx`：工具注册、校验、执行、幂等和循环控制。
- `SEC-xxx`：认证授权、Prompt Injection、SSRF、隐私与日志。
- `E2E-xxx`：浏览器或完整服务链路场景。
- `PERF-xxx`：容量、并发、延迟和资源使用。
- `DR-xxx`：备份、恢复、重启、重放与灾难恢复。

编号一经进入主分支不可复用；删除用例时保留编号并标注 retired。

注意：本文 `SEC-xxx` 表示安全测试用例；`01-product-requirements.md` 中同名的安全需求在追踪矩阵中应写作 `PRD SEC-xxx`，避免把需求编号和测试编号混为一谈。正式实现时建议生成“`FR/NFR/AC/PRD SEC → 测试编号 → CI 结果`”追踪表。

## 4. 测试环境

### 4.1 环境分层

- **local**：Docker Compose 启动 PostgreSQL/pgvector、Redis；FakeLLM、Mock Search、Mock Delivery。
- **CI-unit**：不启动外部服务，固定随机种子，禁止访问公网。
- **CI-integration**：临时 PostgreSQL/pgvector、Redis，执行完整 migration；每个 job 使用独立数据库。
- **CI-e2e**：生产构建的 Web/API/Worker，FakeLLM 与 Mock 外部依赖，浏览器无头运行。
- **staging**：配置接近生产，可选择真实 LLM/搜索做小流量契约测试，使用专用测试账号和配额。
- **release rehearsal**：从备份恢复的隔离环境，运行 smoke、性能和恢复演练。

### 4.2 Fixtures 与测试替身

- `FakeLLM`：按脚本依次返回文本、工具调用、畸形 JSON、429、5xx、超时、空答、重复答或中途断流。
- `MockEmbedding`：确定性向量，支持相等、近似、正交和零向量。
- `MockSearchProvider`：版本化结果，包含可信正文、Prompt Injection 文本、超长正文、重定向 URL 和空结果。
- `MockDeliveryProvider`：写入测试收件箱，可模拟成功、超时、失败、重复回执。
- `FakeClock`：固定时间、推进时间、DST 切换和时区转换。
- `TwoUserFixture`：至少用户 A、B；创建文本相似的记忆和资源以验证隔离。
- `ConversationFixture`：空会话、短会话、恰好达到预算、超预算、已有摘要和压缩失败。
- `ToolFixture`：只读、写入、慢工具、可重试失败、不可重试失败、恶意 URL、超大结果。

测试替身必须实现与生产 adapter 相同的接口；契约测试防止 Mock 与真实实现语义漂移。

## 5. 测试数据边界

每类输入至少覆盖：

- 空值、缺失值、最小合法值、恰好在上限、超过上限。
- 中文、英文、混合文本、emoji、组合字符、RTL 字符、换行、Markdown/HTML。
- 0、负数、最大整数、小数、NaN/Infinity（若协议可能收到）。
- 空 UUID、畸形 UUID、存在但属于其他用户的 UUID。
- 0 条、1 条、分页边界、最后一页、重复游标、失效游标。
- 空消息、纯空白、超长消息、超长单词、超大工具结果。
- UTC、正/负偏移、`Asia/Shanghai`、`America/New_York` DST 跳过/重复时刻。
- Token 预算的 `limit-1`、`limit`、`limit+1`，以及单条消息已超过预算。
- 相似度相同、时间相同、置信度相同，以验证稳定排序。
- 并发写入、重复请求、乱序事件、网络断线、进程重启。
- 包含密码、Token、Cookie、邮箱、手机号、个人偏好的日志样本。

4. `integration`：临时 PostgreSQL/pgvector、Redis，执行 `IT/API/MEM/TOOL`。
5. `security`：secret scan、依赖漏洞、SAST、`SEC` 快速回归。
6. `build`：Next production build、API/Worker 镜像构建。
7. `e2e`：FakeLLM + Mock Search/Delivery 的关键 `E2E`。
8. `nightly/release`：真实 provider 契约、完整 `PERF/DR`、长稳测试。

失败 artifact 应包括测试报告、服务日志和 trace，但必须先脱敏；浏览器截图/视频不得包含真实数据。

## 17. 测试命令模板

具体脚本名在工程脚手架阶段确定，下列命令是建议模板，不代表已经存在或执行：

```bash
# 一键启动测试依赖
docker compose -f infra/compose/test.yml up -d --wait

# Web
pnpm --filter @zhiban/web lint
pnpm --filter @zhiban/web typecheck
pnpm --filter @zhiban/web test
pnpm --filter @zhiban/web build

# API/Worker
uv run ruff check apps/api
uv run mypy apps/api/src

uv run pytest apps/api/tests/integration -m integration

# 契约与迁移
```

CI 应保存命令、退出码、版本与报告；文档中不得手工填写“全部通过”替代执行证据。

## 18. 答辩前 Smoke Checklist

### 环境与数据

- [ ] 当前 commit/tag、构建版本和数据库 migration head 一致。
- [ ] `.env` 使用演示专用账号，无个人/生产密钥。
- [ ] PostgreSQL、pgvector、Redis、API、Worker、Web 均 ready。
- [ ] 执行 `reset-demo` 与 demo seed，无旧会话和旧通知残留。
- [ ] 两个演示用户可登录，数据隔离样例存在。
- [ ] Mock 模式标识清晰；真实 provider 模式与备选模式均确认。

### 主路径

- [ ] 普通流式聊天可完成。
- [ ] 第一次告知偏好后，新会话主动使用该偏好。
- [ ] 明确“忘记”后，新会话不再使用该记忆。
- [ ] 创建并修改提醒，Fake Clock 推进后只投递一次。
- [ ] 搜索后总结包含来源，空结果不编造。
- [ ] 刷新/断线后消息不重复，最终状态可恢复。

### 故障与安全

- [ ] 模型超时/429/5xx 注入后有可读回复，不无限加载。
- [ ] 搜索和投递故障分别有可读降级。
- [ ] Prompt Injection fixture 不改变系统行为。
- [ ] SSRF 私网 URL 被拒绝。
- [ ] 用户 A 不能访问用户 B 的记忆和提醒。
- [ ] 日志抽检无 Token、Cookie、完整记忆或密钥。

### 备选与材料

- [ ] 主机电源、网络、投屏分辨率和浏览器缩放已确认。
- [ ] 本地 Mock 可完全离线运行。
- [ ] 主路径和故障路径录屏可离线播放。
- [ ] 恢复命令、演示脚本、架构图、已知限制均可离线访问。
- [ ] 实测数据与“验收目标”明确区分，没有虚构测试结果。
