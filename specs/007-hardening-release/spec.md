## 2. 背景与问题

`SPEC-001~006` 已实现完整的 P0 功能闭环（认证/聊天/记忆/工具/待办提醒/真实搜索）。但作为答辩交付，还缺稳定性加固与演示固化：

1. **安全未系统化验证**：Prompt Injection、SSRF、越权、日志脱敏虽有零散实现，但缺系统性防护与测试证据。
2. **无 E2E 测试**：只有单元/集成测试，缺浏览器级端到端主路径验证。
3. **无故障注入**：LLM/搜索/投递失败时的降级行为未系统验证。
4. **无演示固化**：缺 seed/demo 账号/reset-demo/演示数据。
5. **无答辩材料**：缺架构图、测试报告模板、已知限制、答辩脚本。
6. **无备份恢复 runbook**。

本 Spec 补齐这些，使项目达到可答辩状态。

## 3. 目标

1. 安全加固：SSRF 防护、Prompt Injection 防护、日志脱敏的系统化实现与测试。
2. 日志脱敏：确保不记录密码/Token/Cookie/完整消息正文/完整记忆。
3. E2E 测试：覆盖登录→聊天→记忆→待办→提醒→搜索的主路径。
4. 故障注入：LLM 失败、搜索失败、投递失败的降级验证。
5. 演示固化：seed/demo 账号/reset-demo/演示数据。
6. 答辩材料：架构图、测试报告、已知限制、运行说明。
7. 备份恢复 runbook 与 smoke 固化。

## 4. 非目标

本步骤不实现：

- 生产级完整监控平台（只做结构化日志 + 基础指标）。
- 完整熔断器矩阵（文档有设计，本 Spec 只做关键依赖的超时+降级）。
- 性能压测（PERF 只做 smoke 级基线，不追求文档里的完整压测）。
- 完整 RBAC、企业级安全。

## 6. 规范要求

### 6.1 安全加固

- **SPEC-HAR-001** 日志 MUST NOT 记录密码、Token、Cookie、完整消息正文、完整记忆正文。
- **SPEC-HAR-002** Prompt Injection：搜索结果/网页内容 MUST 视为不可信数据，不改变系统指令、工具权限。
- **SPEC-HAR-003** SSRF：搜索/URL 工具 MUST 拒绝私网、loopback、云 metadata 地址（当前 SearXNG 是受控 provider，需在 adapter 层确认边界）。
- **SPEC-HAR-004** 越权：所有资源访问 MUST 强制 user scope（SPEC-002 已做，本 Spec 补系统性测试）。
- **SPEC-HAR-005** 敏感字段脱敏 MUST 有自动化测试（日志样本注入密码/Token 验证不泄露）。

### 6.2 E2E 测试

- **SPEC-HAR-010** E2E 覆盖登录→聊天→记忆→待办→提醒的主路径。
- **SPEC-HAR-011** E2E 使用 FakeLLM + Mock 外部依赖，可离线重复运行。
- **SPEC-HAR-012** E2E 至少一条跨用户隔离断言。

### 6.3 故障注入

- **SPEC-HAR-020** LLM 失败/超时 → 可读降级回复，不无限加载。
- **SPEC-HAR-021** 搜索失败 → 明确说明未完成检索，不伪造结果。
- **SPEC-HAR-022** 投递失败 → 重试/死信，不丢任务事实。

### 6.4 演示固化

- **SPEC-HAR-030** seed 幂等，提供 demo 账号 + 演示数据。
- **SPEC-HAR-031** reset-demo 仅在非生产环境运行，环境哨兵双重确认。
- **SPEC-HAR-032** 运行说明覆盖安装/启动/迁移/测试/演示。

### 6.5 答辩材料

- **SPEC-HAR-040** 架构图、测试报告模板、已知限制、答辩脚本。

## 8. 发布与回滚

- 本 Spec 主要是加固 + 测试 + 材料，无破坏性 schema 变更。
- seed/reset-demo 脚本需环境哨兵保护。

## 9. 偏差与决策

| 决策 | 说明 |
|---|---|
| 不实现完整熔断器 | 当前单依赖（Kimi/搜索）已有超时+重试，完整熔断器矩阵对答辩收益低 |
| 监控从简 | 结构化日志 + request_id 已够答辩，不引入 Prometheus/Grafana |
| 性能只做 smoke 基线 | 文档的完整 PERF 压测非答辩必要，做 smoke 级即可 |
