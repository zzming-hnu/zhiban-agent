## 三、问题诊断与修复

### 问题 1：词法降级完全失效（recall=0.000）

- **根因**：`search.py` 用 `Memory.content.ilike(f"%{query}%")` 做整串子串匹配，要求 query 完整出现在记忆内容中。中文场景下（"喝咖啡偏好" vs "美式咖啡不加糖"）几乎无法命中，embedding 服务不可用时记忆检索彻底瘫痪。
- **修复**：引入 `memory/lexical.py`，用 **jieba 分词 + 停用词过滤 + BM25/覆盖率混合打分** 替代 ilike 整串匹配。

### 问题 2：打分阈值与权重是"拍脑袋"的

- **根因**：`MIN_FINAL_SCORE=0.62`、`MIN_MAX_SIGNAL=0.45` 是为旧的"命中=1.0"逻辑调的，换成 BM25 连续打分后，分数整体下移，正确结果被阈值误杀。
- **修复**：把权重和阈值抽象为 `RankerConfig` 可配置对象，用调优脚本在评测集上**网格搜索最优参数**（`min_final_score` 0.62→0.45，`min_max_signal` 0.45→0.20）。

### 问题 3：embedding 为 NULL 时向量检索崩溃

- **根因**：`cosine_distance` 对 embedding 为 NULL 的记录返回 None，`float(None)` 抛 TypeError。
- **修复**：向量召回时跳过 `distance is None` 的记录（降级容忍）。

## 四、技术要点

1. **可评估的检索系统**：建立评测集 + 三个指标（recall/nDCG/MRR），每次改动可量化验证。
2. **中文分词 + 停用词**：jieba 分词，过滤"我/在/有/什么"等高频无意义词，避免共享停用词导致误匹配。
3. **混合打分**：向量相似度 + 词法覆盖率 + 时效衰减（遗忘曲线）+ 重要度 + 置信度 + 类型，六因子加权。
4. **数据驱动调参**：网格搜索替代人工拍脑袋，权重和阈值由评测集决定。
5. **降级健壮性**：embedding 不可用、向量为 NULL 时均能优雅降级到词法检索。

## 五、可解释性输出（阶段 3，已完成）

将记忆检索的"为什么"暴露给用户：

1. **后端**：`search_memories` 返回每条召回的 `breakdown`（向量相似度、词法相关、时效、重要度等各因子得分），通过新增 SSE 事件 `memory.retrieved` 推送给前端。
2. **前端**：对话界面展示"召回了 N 条相关记忆"，每条记忆附带相关度百分比。

示例事件：
```json
{"type": "memory.retrieved", "data": {"memories": [
  {"content": "self 任职于 星辰科技", "score": 0.6116,
   "breakdown": {"lexical": 0.0, "recency": 1.0, "vector": 0.6521}}
]}}
```

## 六、联网搜索质量优化（已完成）

针对搜索"结果重复、来源良莠不齐"的问题，新增 `tools/search/quality.py`：

1. **去重**：URL 归一化（去 tracking 参数、锚点、www）+ 标题相似度（>0.85 判重），去除多引擎返回的重复结果。
2. **源可信度分级**：权威媒体（gov/edu/百科/凤凰/网易/CSDN/知乎/GitHub 等）1.0、中等社区 0.7、个人博客 0.4，按可信度排序，让 AI 优先采用权威来源。
